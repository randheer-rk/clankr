Agents, described like infrastructure. Run like it, too.

You write agents and workflows as resources. Clankr schedules them onto your machines in sandboxes, keeps every step in Postgres so nothing is lost on a crash, and sits between agents and every model, tool and credential they use.

What breaks at scale, and what the engine does about it

RefFailureResponse
F-01A node dies three hours into a jobWorkflow state is event-sourced. Each step commits with the work it schedules, so the run resumes at the last committed event on another node. Replay calls no model twice. epoch-fenced leases reject stale writes.
F-02An agent runs code you didn't writeRootless container, gVisor or Firecracker microVM, read-only, no network unless granted. Listed hosts go through a per-agent proxy; everything else is refused and logged.
F-03A loop spends the month's budget by lunchTokens are reserved from a budget before every model call and settled after, per namespace and per run. The gateway refuses when the budget is gone.
F-04An action needs a personApproval steps and approval-gated tools park the run in an inbox. Who said yes, and when, is in the audit log.
F-05"What exactly happened?"Every run has a complete event history. View it as it stood after any event, or fork a new run from there. Privileged actions are hash-chained and shipped off-site; clank audit-check verifies them.
