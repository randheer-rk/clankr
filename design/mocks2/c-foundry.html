Agents that
work shifts,
not demos.

Clankr runs your AI agents like a plant runs machines: each one sandboxed on a node, every step logged before it happens, every key kept at the gate. When a machine fails, the job carries on. When a tool needs sign-off, it waits for you.

Plate 01

It picks up where it fell.

Every workflow step is an event in Postgres, committed together with the work it schedules. A node dies, the run moves, and resumes at the last line. No model is ever called twice.

#15 node.lost        eu-1
#16 step.resumed     draft ← #14
Plate 02

Keys stay at the gate.

Agents name a claim; the gateway on their node holds the real key, reserves budget before the call and settles after. A runaway loop hits the budget, not your card.

Plate 03

Some levers need a hand.

Mark a tool as approval-gated and the run parks in an inbox until a person says yes. The decision, and who made it, goes in the hash-chained audit log.

$ clank approve a-91c2 --reason "ship it"
audit #14,212 ✓ sealed

No Kubernetes.
No Temporal.
One binary.

clankrd is the whole control plane: API, scheduler, workflow engine, gateway, inbox and web UI, on a Postgres you already know how to back up. clankr-node is a small daemon on each machine that dials in over mTLS and runs agents under kennel, in containers, gVisor, or Firecracker microVMs.

Write agents in Python, TypeScript or Go with an SDK that hands you work and messages. Describe them in YAML. clank apply. That's the job.
