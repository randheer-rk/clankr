Every step your agents take, written down before they take it.

Clankr is an orchestration engine for AI agents. It runs them sandboxed on your machines, keeps each workflow as a log of events in Postgres, and brokers every key, budget and tool call. This page is one of those logs.

run.started

You describe it. Clankr schedules it.

Agents, models, tools and workflows are resources, like Kubernetes objects but without Kubernetes. clank apply, and the scheduler places each agent on a node in a sandbox: a rootless container, gVisor, or a Firecracker microVM.

kind: Workflow
spec: { entrypoint: draft, nodes: { draft: { agentRef: writer }, review: { agentRef: reviewer } } }
00:00.340
model.call.reserved

Keys and budgets never enter the sandbox.

The agent names a claim. The gateway on its node holds the real credential, reserves tokens from the namespace budget before the call, and settles the actual cost after. Who spent what is in the ledger.

00:31.502
node.lost

The machine died. The run didn't.

Each step commits in the same Postgres transaction as the work it schedules. When a node's lease expires, the instance is rescheduled with a new epoch and resumes from the last committed event. Stale writes from the old node are refused. No model or tool is called twice.

#15 node.lost          eu-1 · epoch 41
#16 instance.rescheduled  writer → eu-2 · epoch 42
#17 step.resumed       draft ← #14
00:34.004
approval.requested

Some tools wait for a person.

Publishing, paying, deleting: gate the tool, and the run parks in an inbox for a minute or a week. The answer, and who gave it, is appended here and to a hash-chained audit log shipped off-site.

00:34.220
message.sent

Agents talk through the node, durably.

Services with stable names, request/reply with timeouts, topics with durable subscriptions. A subscriber that was down catches up. A reply that arrives late never haunts its caller.
