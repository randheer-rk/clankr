# 0038 — A2A: agent cards and calling outside agents

Status: accepted (2026-11-04)

**Context.** Agents in a cluster talk through services (ADR 0033); agents elsewhere, in other products and clouds, increasingly speak A2A (Agent2Agent, v1.0 in 2026, JSON-RPC binding). The request/reply model is the same shape, so the bridge is thin in both directions.

**Decision.**

- **Serving.** Every `AgentService` is an A2A agent. `GET /a2a/{ns}/{svc}/.well-known/a2a/agent-card.json` is its card (name, `spec.description`, `spec.skills` or one skill named after the service, bearer security, `protocolVersion: "1.0"`, a `json-rpc` interface at `POST /a2a/{ns}/{svc}`). The card's URL is built from `CLANKR_PUBLIC_URL`, else `x-forwarded-proto` and `Host`.
  - `SendMessage`: the message's text parts (joined) and first data part become the service request `{text, data, from: "a2a:<principal>", messageId, contextId}`, deduplicated per caller and `messageId`. The reply (ADR 0033's string or `{text, …}`) comes back as a `ROLE_AGENT` Message: a text part, plus a data part for the rest.
  - **Tasks.** With `configuration.returnImmediately`, or when no reply arrives within 60 s, the result is a Task whose id is the request's message id. `GetTask` reads the request's reply queue: a reply makes it `COMPLETED` with the reply as `status.message`; a dead-lettered request is `FAILED`; leased is `WORKING`; otherwise `SUBMITTED`.
  - Cards and calls take a bearer token like the rest of the API (RBAC: `ResourcesRead` for the card, `WorkExecute` to send). Cards are not public.
- **Calling.** Tool executor `a2a {url, secretRef?, header}`. Each method sends one message, `input.text` as a text part and the rest of the input as a data part, then follows a Task with `GetTask` every two seconds until it finishes or the tool's timeout runs out (`OutcomeUnknown` then, like any unsafe tool). The output is `{text, data, parts}`. The credential is brokered like `http` tools; a bare token in `authorization` gets its `Bearer` prefix.

**Consequences.**
- No new storage: Tasks are the mailbox requests they already were, which is why there's no `ListTasks` or `CancelTask` (-32601).
- Not yet: streaming (`SendStreamingMessage`, `SubscribeToTask`), push notifications, file parts, `INPUT_REQUIRED` round trips from a tool call, agent-card signing, and the extended card.
